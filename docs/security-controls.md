# Security Controls

Status: v0.10.0 tagged and published; v0.11.0 pentest PASS, awaiting hosted checks and signed tag

| Control | Foundation enforcement |
| --- | --- |
| Dependency surface | Cargo manifests and `cargo metadata` must contain no external packages |
| CI tool provenance | Exact versions and independently pinned `.crate` SHA-256 hashes are verified before installing security and SBOM tools |
| Unsafe Rust | Workspace lint denies it by default; a machine inventory permits exactly one documented volatile-store block in one private v0.11 module and rejects every other allowance, unsafe block/item, assembly, or FFI site |
| `no_std` | Every package declares `#![no_std]` |
| Package classification | Committed policy classifies all 24 packages and exact direct, optional, feature, target, source, and publication boundaries |
| Modern/legacy isolation | No-default and all-feature graph validators reject either facade reaching the other package class, research, or repository tooling |
| TLS version isolation | Both resolved graphs require the evergreen router to reach separate TLS 1.2 and TLS 1.3 engines while QUIC reaches only the recordless TLS 1.3 handshake |
| Review size | Source files over 500 lines fail checks |
| Toolchain | Rust 1.97.1 release pin plus explicit 1.90.0-1.97.1 matrix; Kani 0.67.0 is separately paired with Rust 1.90.0 and cannot constrain or redefine normal builds |
| Assurance harness | First-party deterministic mutation/replay and canonical external-process differential runners enforce public-test-input, case-count, timeout, simultaneous output, no-shell, parser, class, adapter-count, and mismatch boundaries; campaign OS sandboxing remains an explicit caller duty |
| Bare metal | Complete all-feature workspace compiles on ARMv7E-M, RV32IMAC, and x86_64 OS-less targets without claiming runtime or platform services |
| External assurance tools | Exact Kani, AFL++, honggfuzz, Miri, and sanitizer version/revision pins are machine checked and forbidden from Cargo manifests; policy-only or skipped evidence is never a proof |
| Standards | Exact HTTPS host/path and redirect allowlists, independently reviewed non-self-replacing pins, bounded responses, DTD/entity rejection, 103 immutable RFCs, 15 local-only NIST/ITU authorities, exact RFC-index and eight IANA snapshots, 290 reviewed errata decisions, lifecycle and milestone ownership, complete updated-by/obsoleted-by closure, deterministic ledger generation, broken fixtures, and release-time live drift rejection |
| Protocol surfaces | Deterministic classification of 126 semantic decisions, 195 nested registries, and 4,124 individual records across all eight pinned IANA collections with exact source-ledger binding, disposition, milestone, code target, test target, and broken-fixture enforcement |
| Failure domains | All 256 alert registry bytes retain assigned, reserved, or unassigned identity; local alert selection is protocol-version-aware; close and cancellation cannot enter `TlsFailure`; failure envelopes accept no arbitrary text or bytes and implement no formatting traits |
| Numeric and resource domains | Private-field compile-time bounds, checked arithmetic, distinct count/length types, fail-closed pointer-width conversion, non-wrapping sequence/epoch advancement, named single-assignment immutable budget construction with typed duplicate/incomplete-domain errors and without positional arguments, defaults, or mutable setters, and limit-value-free typed exhaustion are enforced by exhaustive small-domain matrices, every-domain duplicate and omission tests, boundary tests, representation tests, a workspace-wide overlong-argument lint, and compile-fail doctests |
| Borrowed read cursor | Private input/position state, checked end offsets, bounds-checked slice access, exact dynamic/typed/fixed-array borrowing, success-only advancement, consuming trailing-data checks, non-clonable and non-formattable cursor state, and value-free errors are enforced by every-position/request matrix tests, truncation at every byte, every trailing suffix, overflow/zero-length/identity/storage tests, compile-fail doctests, and the workspace no-indexing lint |
| Transactional write cursor | Private output/position state, exclusive caller-buffer borrowing, checked complete-range and aggregate-part preflight, exact single-slice/multi-part/repeated-byte mutation, success-only advancement, byte-for-byte failure preservation, immutable written-prefix inspection, consuming exact-capacity completion, non-clonable and non-formattable cursor state, and value-free errors are enforced by every-position/request matrices, whole-buffer sentinels, multi-part, overflow, zero-length, empty-output, identity/storage, compile-fail, `no_std`, and no-indexing tests |
| Workspace and arenas | Named single-assignment secret/plaintext/transcript/certificate/output layout, checked aggregate length, exact backing-length admission, one safe fixed-order split, sealed zero-sized compile-time domain identities, named simultaneous domain borrows, monotonic complete-range allocation, per-domain high-water and successful non-empty allocation counters, retained-byte complete-initialization duty, byte- and accounting-transactional failures, private non-clonable/non-formattable state, and value-free errors are enforced by every-domain duplicate/omission checks, exhaustive small layouts, every-position/request matrices, overflow/exhaustion/zero-length/sentinel/pointer-identity/isolation/representation tests, compile-fail exclusive-borrow/domain-swap tests, `no_std`, and no-indexing policy; domain names classify raw storage only, certificate storage is not private-key storage, and sensitive consumption is prohibited until v0.10 lifetime states and the v0.11 proven destruction primitive exist |
| Secret lifecycle | The v0.10 abstract contract retains all-target destruction duties and failed-Drop handling; v0.11 separately owns one complete caller allocation by exclusive borrow, clears old bytes before write-only sequential initialization, admits read access only after exact completion, and clears the complete region on incomplete finish, both Drop paths, or explicit clear |
| Owned-memory zeroization | One private per-byte volatile-store loop plus compiler barrier is checked at MIR, LLVM IR, and assembly levels across ten stable compilers and nine targets, with pinned Miri and AddressSanitizer; the exact claim excludes registers, copies, caches, DMA-visible copies, dumps, suspend images, physical memory, concurrency, forgotten owners, and termination |
| Test-only key logging | All pinned RFC 9850 labels and three line endings are implemented transactionally only in permanently unpublished `brynja-test-support`; workspace metadata and negative fixtures reject every production dependency, optional dependency, feature, target edge, publication flag, and resolved-graph path to the package |
| Normative requirements | 167 stable identifiers bind exact source, section, status, errata, authority role, strength, applicability, decision, mapping scope, owner, lifecycle, revision, assurance invariants, work bound, residual risk, target, positive and negative tests, and evidence gap; the generated closure covers all 126 authorities, 206 roadmap rows, and 4,445 surfaces, including 50 residual requirements, 33 residual authorities, 182 reviewed residual normative sections, 165 mapped sections, 17 explicit exclusions, and 764 formerly uncovered surfaces; immutable history and 110 requirement fixtures plus four surface-security fixtures reject omissions, undeclared evidence dispositions, orphaned cross-bundle delegations, semantic RFC 6066 laundering, TLS 1.2 authority omissions, wire/configuration conflation, non-reciprocal or boundary-mixed surface groups, wrong protocol ownership, actionable source-blocked legacy requirements, blanket section inheritance, drift, role errors, stale revisions, illegal transitions, unrelated mappings, weak bounds, missing anchors, rights gaps, stale mutable guidance, orphaned plans, repository-escaping targets, and premature claims |
| Authority refresh and rights | Every local NIST/ITU source is local-only with an explicit distribution review; all eight mutable IANA registries and five dependent NIST publication pages have exact refresh owners; unavailable hybrid, legacy-source-rights, and FIPS-validation baselines remain machine-readable blockers |
| Hybrid admission | Concrete ECDHE-ML-KEM groups remain blocked until both a final Standards Track RFC and final IANA code points exist; drafts and private values are forbidden |
| Tags and releases | Every roadmap version requires a signed commit, complete automated tag gate, clean GitHub and CodeQL, explicit authorization, exact immutable signed annotated tag, release notes, and SBOM; scheduled or exceptional public checkpoints additionally require a backwards-looking cumulative PASS/PASS report with zero open findings and a strict publisher-context gate |
| GitHub protection | Active machine-checked main ruleset requires signed linear history, review and CodeQL while retaining explicit accountable owner/admin bypass |
| CI | Read-only permissions, full-SHA action pins, live release-control verification, Clippy enforcement for both all-feature and no-default-feature configurations, stage-aware acceptance of development milestones without scheduled reports, and fail-closed PASS/PASS or remediation-stage RETEST REQUIRED/PENDING validation whenever a current report exists |
| CodeQL | GitHub Default setup; no advanced workflow |
| Panic posture | Panics are forbidden by workspace lint; release builds retain overflow checks and abort if an otherwise unreachable panic occurs, accepting process termination as the final fail-closed response rather than permitting recovery from a violated invariant |
