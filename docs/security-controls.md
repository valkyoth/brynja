# Security Controls

Status: v0.10.0 published; v0.11.0-v0.14.0 tagged; v0.15.0 awaiting green CI

| Control | Foundation enforcement |
| --- | --- |
| Dependency surface | Exactly one external package is admitted: exact first-party `sanitization 2.0.3`, reachable only through separately selected `brynja-sanitization`, with package/source hashes, no default or selected feature, no transitive package, inherited unsafe inventory, online freshness, and broken-fixture enforcement; every other external package is rejected |
| First-party Rust cryptography | The permanent golden rule requires every Brynja primitive, construction, key operation, protocol cryptographic operation, CPU backend and FIPS service to be implemented from first-party Rust source; policy rejects foreign/native source and binary artifacts, build scripts, build dependencies, Cargo native-link metadata, foreign ABIs, native link attributes and included native binaries, with nine broken fixtures; separately gated Rust intrinsics or inline assembly remain Brynja-owned symbols, never external modules |
| CI tool provenance | Exact versions and independently pinned `.crate` SHA-256 hashes are verified before installing security and SBOM tools |
| Unsafe Rust | Workspace lint denies it by default; a machine inventory permits exactly one documented volatile-store block in one private v0.11 module and rejects every other allowance, unsafe block/item, assembly, or FFI site |
| `no_std` | Every package declares `#![no_std]` |
| Package classification | Committed policy classifies all 27 packages and exact direct, optional, external, feature, target, source, and publication boundaries |
| Modern/legacy isolation | No-default and all-feature graph validators reject either facade reaching the other package class, research, or repository tooling |
| TLS version isolation | Both resolved graphs require the evergreen router to reach separate TLS 1.2 and TLS 1.3 engines while QUIC reaches only the recordless TLS 1.3 handshake |
| Review size | Source files over 500 lines fail checks |
| Toolchain | Rust 1.97.1 release pin plus explicit 1.90.0-1.97.1 matrix; Kani 0.67.0 is separately paired with Rust 1.90.0 and cannot constrain or redefine normal builds |
| Assurance harness | First-party deterministic mutation/replay and canonical external-process differential runners enforce public-test-input, case-count, timeout, simultaneous output, no-shell, parser, class, adapter-count, and mismatch boundaries; campaign OS sandboxing remains an explicit caller duty |
| Bare metal | Complete all-feature workspace compiles on ARMv7E-M, RV32IMAC, and x86_64 OS-less targets without claiming runtime or platform services |
| External assurance tools | Exact Kani, AFL++, honggfuzz, Miri, and sanitizer version/revision pins are machine checked and forbidden from Cargo manifests; policy-only or skipped evidence is never a proof |
| Standards | Exact HTTPS host/path and redirect allowlists, independently reviewed non-self-replacing pins, bounded responses, DTD/entity rejection, 104 immutable RFCs, 15 local-only NIST/ITU authorities, exact RFC-index and eight IANA snapshots, 290 reviewed errata decisions, lifecycle and milestone ownership, complete updated-by/obsoleted-by closure, deterministic ledger generation, broken fixtures, and release-time live drift rejection |

| Borrowed read cursor | Private input/position state, checked end offsets, bounds-checked slice access, exact dynamic/typed/fixed-array borrowing, success-only advancement, consuming trailing-data checks, non-clonable and non-formattable cursor state, and value-free errors are enforced by every-position/request matrix tests, truncation at every byte, every trailing suffix, overflow/zero-length/identity/storage tests, compile-fail doctests, and the workspace no-indexing lint |
| Transactional write cursor | Private output/position state, exclusive caller-buffer borrowing, checked complete-range and aggregate-part preflight, exact single-slice/multi-part/repeated-byte mutation, success-only advancement, byte-for-byte failure preservation, immutable written-prefix inspection, consuming exact-capacity completion, non-clonable and non-formattable cursor state, and value-free errors are enforced by every-position/request matrices, whole-buffer sentinels, multi-part, overflow, zero-length, empty-output, identity/storage, compile-fail, `no_std`, and no-indexing tests |
| Workspace and arenas | Named single-assignment secret/plaintext/transcript/certificate/output layout, checked aggregate length, exact backing-length admission, one safe fixed-order split, sealed zero-sized compile-time domain identities, named simultaneous domain borrows, monotonic complete-range allocation, per-domain high-water and successful non-empty allocation counters, retained-byte complete-initialization duty, byte- and accounting-transactional failures, private non-clonable/non-formattable state, and value-free errors are enforced by every-domain duplicate/omission checks, exhaustive small layouts, every-position/request matrices, overflow/exhaustion/zero-length/sentinel/pointer-identity/isolation/representation tests, compile-fail exclusive-borrow/domain-swap tests, `no_std`, and no-indexing policy; domain names classify raw storage only, certificate storage is not private-key storage, and sensitive consumption is prohibited until v0.10 lifetime states and the v0.11 proven destruction primitive exist |
| Secret lifecycle | The v0.10 abstract contract retains all-target destruction duties and failed-Drop handling; v0.11 separately owns one complete caller allocation by exclusive borrow, clears old bytes before write-only sequential initialization, admits read access only after exact completion, and clears the complete region on incomplete finish, both Drop paths, or explicit clear |
| Owned-memory zeroization | One private per-byte volatile-store loop plus compiler barrier is checked at MIR, LLVM IR, and assembly levels across ten stable compilers and nine targets, with pinned Miri and AddressSanitizer; the exact claim excludes registers, copies, caches, DMA-visible copies, dumps, suspend images, physical memory, concurrency, forgotten owners, and termination |
